# 同类插件调研：DSH 上「会话总结 / 交接 / 新会话」的现状

> 检索时间：2026-10-23。来源：GitHub 搜索（`topic:dsh-plugin` 组合 handoff / summary / session / memory）、
> [dshfind 插件超市](https://dshfind.com/zh) 索引、本机 profile 已装插件源码、各仓库 README。
> 星数为检索时快照，仅用于判断相对热度，不代表质量。

---

## 0. 结论先行

**没有找到一个与本插件完全同形的插件。** 现有生态分成四类：

1. **会话迁移/交接类**：`dsh-plugin-bridge`、`dsh-context-zip`、`dsh-auto-memory`、`dsh-session-bridge`；
2. **会话导航/分支类**：`dsh-synapse`、`dsh-rewind`、`dsh-turn-delete`；
3. **记忆类**：`dsh-mnemon`、`dsh-meow-memory`、`dsh-mneme`、`dsh-memento`、`graph-memory` 等；
4. **上下文洞察/自动化类**：`dsh-context`、`dsh-automation`。

最接近的是 **`dsh-plugin-bridge`**（跨预设迁移 + 五段式 handoff + 预览确认），但它的入口是会话菜单/快捷键/命令，
目标是「换预设」，产物是「迁移到目标预设的新会话」；**没有一个插件把入口放在提交按钮旁**，
也**没有一个把「工作总结文档 + 记忆台账 + 新会话提示词」当成一个可审阅的交接包**。

这正是本插件的空位：**把「交接」从一个迁移流程，降维成输入框旁的一次点击。**

## 2. 逐个要点

### 2.1 dsh-plugin-bridge —— 最值得对标的方案

README 的核心叙事：*"Halfway through a task and need another tool preset? … Bridge previews a bounded five-part
handoff, opens a clean target, and leaves the original session untouched."*

它的完整链路值得我们学习：

- **五段式 + 有界**：handoff 有固定 schema 与长度上限，避免摘要失控；
- **预览 / 编辑 / 确认**：`/bridge code` 只预览，`--go` 才执行，`--continue` 顺带开工；
- **多入口**：菜单动作、快捷键、斜杠命令、自然语言；`commandview` 原生卡片；
- **自检**：`/bridge --doctor` 检查宿主契约（DSH 升级后先跑）；
- **降级**：没有 UI 宿主时，保留服务端结果 + summary 文件 + `/bridge code --go --file <path>`；
- **明确边界**：源会话不动、确认态在内存（重启丢弃预览）、不自动执行。

**它没有覆盖的空位**：

1. 入口是「会话菜单/命令」，不是输入框旁的常驻动作；
2. 目标语义是「跨预设迁移」，因此必须携带预设相关的迁移决策，交接文档不是「工作总结」；
3. 它的确认是「迁移前确认」，用户仍需读一遍长摘要；我们选择「预填草稿」，把确认放在新会话的输入框里，
   顺手就能改，交互更短；
4. 没有「记忆台账」这一层。

### 2.2 dsh-context-zip —— 同一问题的「压缩侧」解法

它明确接管 DSH 的压缩后端，把自由摘要替换成五段式交接摘要（Goal and intent / Decisions / Current state /
Next steps / Anchors），并把被替换原文放进分段目录，提供 `history_segments/read/search/find` 与 `/zip-export`。

值得借鉴：

- **五段式是社区共识**（Bridge、context-zip 各自独立收敛到相似结构）；
- **原文可回查**：摘要不是唯一真相，原始日志仍可定位；
- **不往会话日志写事件**（README 明确），与我们一致；
- **安装有「接管」步骤**：需要设置面板里点一次、重启一次——说明「替换宿主能力」比「新增座位」脆弱得多。

差异：它解决「上下文快满、必须先压缩」，我们解决「上下文已经够了、但想换一个干净会话继续」。
两者可以共存：压缩后的摘要会出现在日志的 `compaction/summary` 事件里，我们的采集器已经把它纳入输入。

### 2.3 dsh-auto-memory —— 「交接账本」的自动流派

它的卖点是「跨窗口 · 跨会话 · 跨工具」：系统提示前主动召回、三层自动沉淀、技能固化、Astra 式上下文管理
（handoff ledgers、PLAN 白板、水位感知）。

差异：

- **触发方式**：它自动；我们显式。自动适合「不想管」，显式适合「要交接给谁、要留档、要审阅」；
- **产物**：它的账本是内部记忆结构；我们的 `WorkSummary.md` 是可直接给人读、进 Git、发给同事的文档；
- **可控性**：我们把「记忆候选」显式列出来、去重、落台账，用户能看到写了什么。

### 2.4 记忆插件群 —— 它们解决「记住」，不解决「交出去」

`dsh-mnemon`（已装）、`meow-memory`、`mneme`、`memento`、`graph-memory` 都在做跨会话记忆：
分层、检索、整合、图谱。它们与我们的关系是**互补**：

- 记忆插件的输入是「值得长期记住的事实」，通常是 Agent 主动写入或用户点一下；
- 我们的输入是「一次会话的完整工作状态」，输出是「交接文档 + 记忆候选」；
- **v0.2 计划**：把 `memoryCandidates` 通过适配器交给已装的记忆插件（mnemon 的项目档案/记忆空间），
  而不是另起一套长期记忆。v0.1 先用 `交接记忆.md` 这个最小可读台账。

### 2.5 会话导航/分支类 —— 不是竞品，是替代动作

- `dsh-synapse`：把会话做成画布与分支，适合「探索」；
- `dsh-rewind`：同窗口回退，适合「走错了」；
- `dsh-turn-delete`：删一轮；
- 官方内建 `ctx.sessions.fork`：复制历史分支。

它们都在「保留历史」这条轴上；我们在「卸载历史、只留结论」这条轴上。两种需求都真实，不能互相替代。

## 3. 市场空位（我们的差异化）

| 维度 | 现有最好（Bridge） | 本插件 |
|---|---|---|
| 入口 | 菜单 / 快捷键 / 命令 | **提交按钮旁的常驻座位**（`conversation.input.right`） |
| 目标 | 换预设迁移 | **任意原因的新会话接力**（上下文满、换模型、交接、留档） |
| 产物 | 五段摘要 + 可选 summary 文件 | **五段交接文档 + handoff.json + 记忆台账 + 可直接发送的提示词** |
| 确认 | 预览卡逐段确认 | **预填草稿**（在新会话输入框里改，零额外弹窗） |
| 记忆 | 无 | **候选提炼 + 去重台账**（v0.2 接记忆插件） |
| 参考文件 | 迁移上下文 | **自动从工具调用提取文件清单，写进提示词与文档** |
| 失败姿态 | 命令/文件兜底 | **确定性摘要兜底 + 端点/座位/能力三级降级** |
| 成本 | 摘要 + 迁移 | **一次摘要调用；新会话只带结论，不带历史** |

一句话：**Bridge 是「换预设的搬家车」，我们想做成「随手存档并续摊的便签」。**

## 4. 可复用模式与要避开的坑

### 可复用

1. **固定 schema**（五段 + 记忆候选 + 参考文件），让摘要可校验、可预览、可编辑；
2. **有界摘要**（字符/token 预算），避免把长会话原样塞进第二次调用；
3. **降级路径**（命令/文件/复制剪贴板），保证 UI 能力缺失时仍可用；
4. **doctor/health 自检**：DSH 升级后先确认宿主契约；
5. **不写会话日志**：交接是旁路，不进模型上下文。

### 要避开

1. **私有 DOM/CSS 克隆**：本工作区某自研插件用 `button[class*="newSession"]` + MutationObserver 放侧栏按钮，
   上游改 CSS Modules 命名即断。我们只用 slot。
2. **接管宿主能力**（压缩后端、模型路由）：升级即碎，需要「接管/重启」步骤；我们只新增座位与端点。
3. **不经确认的自动发送**：默认草稿，`autoSend` 是可选项且失败回退。
4. **把摘要写进会话日志**：会污染上下文与压缩语义。
5. **在插件里造一套私有会话状态**：会话创建/打开一律走 `uiWorkspace` / `sessions`，不自造导航。

---

## 5. 结论

- 生态里「总结」和「记忆」都不缺，「交接」也有 Bridge 这样的成熟方案；
- 缺的是**低摩擦入口 + 可留档产物 + 记忆闭环 + 干净新会话**这四件事的组合；
- 我们的实现策略因此是：**用官方 A 级接缝（slot / sessionQuery / llm / webServer）做主线，
  用 B 级能力（sessions.retain）只做可选增强，所有增强都有降级**。
