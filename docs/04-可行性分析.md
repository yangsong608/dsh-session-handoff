## 2. 关键假设与验证

### 2.1 按钮座位真的存在且为空

- 编译期契约（`slot-catalog.ts`）已收录 `conversation.input.right`：`kind: list`、`scope: session`、
  `summary: 'Compact controls before the composer submit action.'`、`occupants: []`、`replaceRisk: none`；
- 声明在 `contract/slots.ts:278`，渲染在 `InputBar.tsx:475`，父级 owner 为 `conversation.composer.bar`（InputBar）；
- 本插件已在浏览器半把座位名写进产物并通过自检（按钮注册字符串 + 降级座位）；
  `smoke-client.mjs` 进一步用真实 bundle + 真 React SSR 渲染出按钮与预览卡（aria-label、动作、参考文件候选均正确）。

**结论**：不是 DOM hack，是官方组合座位。风险只剩「未来版本改名」，已准备降级座位。

### 2.2 会话历史能读到「工具级」细节

- `sessionQuery.readSession` 返回完整原始日志（含 `tool/call`、`tool/result`、`request/header`、`compaction/summary`）；
- 若没有 sessionQuery，`session.deriveMessages()` 只能给出 surface 消息（无工具参数），已作为降级路径；
- 采集器对未知事件类型全部忽略，日志格式演进不会导致崩溃。

**结论**：能支撑「做过什么、改了哪些文件、跑过哪些命令、在哪失败」的事实级总结。

### 2.3 模型调用可控且可失败

- `GenerateOptions.provider/model` 必填 → 不猜路由：显式配置 > 会话最近 `request/header` > 降级；
- `signal` + `timeoutMs` 支持取消；`finish.reason.kind !== 'stop'` 统一判失败；
- 输出解析失败、超时、无路由、无 llm 四条失败路径全部落到确定性摘要（smoke 已覆盖「无 llm」）。

**结论**：模型是增强项而非单点故障。最坏情况仍产出可用文档。

### 2.4 新会话创建与提示词注入

- 官方路径：`uiWorkspace.startSession(workspaceId?, { prompt })`，`prompt` 初始化草稿（不自动发送）；
- 目标工作区省略时继承「当前/最近工作区」，与 DSH 侧栏「新建会话」的语义一致；
- 半公开路径：`sessions.create({}) + retain + prompt(…, 'queue')`，多个第三方插件在用（本机 `dsh-workbench` 实证），
  作为 `autoSend` 的实现，失败自动回退草稿。

**结论**：默认路径是官方服务；自动发送是可选增强。

### 2.5 参考文档如何「带过去」

- v0.1：把交接文档与参考文件的**绝对路径**写进提示词，新会话 `cwd` 相同，Read 工具可直接打开；
- 参考文件来自工具调用参数提取（路径/命令）+ 模型归纳的 `state.files`；
- v0.2：接入 `@` 引用 chip（社区已有 `dsh-reference-anything` 证明可行），让文件以引用对象进入输入框。

**结论**：v0.1 的纯文本指针已经满足「带着参考文档继续工作」，成本最低、兼容性最好。

### 2.6 记忆固化（唯一需要「设计」的诉求）

DSH 没有内建的跨会话记忆 seam；生态里每个记忆插件自成体系，且**没有公开的写入协议**。直接写别人的库 =
把插件绑到私有存储上，升级必碎。因此：

- v0.1：模型产出 `memoryCandidates`（带 scope：memory/user/project）→ 去重写入 `<dir>/交接记忆.md`；
  用户可读、可改、可删；文档里同时保留「记忆候选」小节；
- v0.2：适配器模式——探测已装记忆插件的公开工具/服务，把候选交给对方去重归档；
- 不直接写运行时 `MEMORY.md` / `USER.md`（每轮注入的预算敏感资源，且需要用户确认）。

**结论**：可行且自洽；「固化」的第一版目标是「可追溯、可审查、不丢」，而不是「自动污染全局记忆」。

## 3. 与替代方案的对比

| 方案 | 上下文成本 | 产物 | 用户摩擦 | 适用 |
|---|---|---|---|---|
| **本插件（总结 + 新会话）** | 低（只带结论 + 指针） | 文档 + JSON + 台账 | 一次点击 + 一次发送（默认） | 上下文满、换模型/预设、交接、留档 |
| `ctx.sessions.fork` 历史 | 高（整段历史继承） | 无（历史即上下文） | 菜单操作 | 需要逐字保留上下文的分支 |
| DSH compaction（`/compact`） | 中（摘要替换 surface） | 会话内摘要 | 命令 | 同一会话继续、只想腾上下文 |
| `dsh-plugin-bridge` | 中（五段 handoff） | 摘要 + 目标预设会话 | 预览/编辑/确认 | 换工具预设 |
| `dsh-context-zip` | 中 | 五段摘要 + 分段原文 | 自动/命令 | 压缩时可回查 |
| 手工复制粘贴 | 不可控 | 无 | 高 | 应急 |

**结论**：本插件不与 fork/compaction 竞争，而是补上「卸载历史、保留结论」这一档。
四者可以共存：压缩过的历史会作为 `compaction/summary` 进入我们的采集输入。

## 6. 成本与收益

- **摘要成本**：一次 4–8 万输入 token + ≤4k 输出；相对 fork 整段历史（10 万+ token）低一个数量级；
- **收益**：省掉「重新讲一遍」的时间；交接文档可复用（同事/下次会话/Git 归档）；
- **风险成本**：默认草稿避免误发送；确定性兜底避免「模型挂了就不能交接」；记忆台账可删改避免污染。

## 9. 结论与建议

1. **技术可行**：核心链路（座位 → 读日志 → 模型归纳 → 落盘 → 新会话）全部落在官方 A 级接缝上，
   本仓库已给出可构建、可自检、可冒烟的 v0.1 实现。
2. **产品有价值**：生态里「交接」要么是迁移流程（Bridge），要么是压缩/记忆（context-zip、mnemon），
   缺少「低摩擦入口 + 可留档文档 + 干净新会话」的组合。
3. **建议节奏**：先以 v0.1 在作者本机 desktop profile 实测 2 周（覆盖 5 次真实交接），
   再补 v0.2 的预览编辑卡与记忆适配器，最后发 npm 并进 dshfind/市场。

**Go / No-Go：Go。** 前提是 §5 的第 1、2、4 项实测通过；任一项不通过，只需调整座位或改用
`conversation.session.header.utilities`，核心能力（文档 + 新会话）不受影响。
