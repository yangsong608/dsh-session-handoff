## 1. 范围（设计 → 可执行项）

设计文档把 v0.2 定义为「预览/编辑卡、@ 文件引用、记忆插件适配器、快捷键、/handoff 命令」。
实施前逐项做了可行性判定，决定 **做 3 项、替代 1 项、延期 1 项**：

| 设计项 | 决策 | 理由 |
|---|---|---|
| 预览/编辑卡 | ✅ 实施 | `shell.overlay` 是 root 级 list 座位，点击穿透、条目自管指针事件，适合模态卡 |
| 参考文件（@ 引用） | 🟡 以「勾选 + 路径清单」替代 | DSH 未公开「编程式插入引用 chip」的稳定 API；提示词里的路径清单已可被 Read 工具直接消费 |
| 记忆插件适配器 | 🟡 保留独立台账 + 预览展示候选 | mnemon 等记忆插件无公开写入协议，直接写私有存储会在升级时碎 |
| 快捷键 | ✅ 实施 | `ctx.shortcuts.register` 为公开 API，需声明六设备档默认键位 |
| `/handoff` 命令 | ⏭ 延期 v0.3 | 命令结果是文本、不能导航/创建会话；只产出文档的命令与按钮重复，价值有限 |

## 3. 架构与模块变更

```text
src/host/
├── render.ts        # 新增 PromptParts / composePrompt；buildPromptText 改为 parts → 文本
├── index.ts         # prepare 返回 promptParts/preview；health 暴露 preview
├── config.ts        # 新增 preview（默认 true）
└── types.ts         # PromptParts、HandoffResult.promptParts/preview

src/client/
├── index.ts         # 三入口：按钮 / 快捷键 / 预览；trigger() 统一链路
├── store.ts         # 预览状态 + 最近活跃会话（模块级可观察单例）
├── compose.ts       # 与服务端逐字一致的提示词组装
├── open.ts          # 新会话三级降级（startSession → sessions → 报错）
├── preview.ts       # 可编辑预览卡（shell.overlay）
└── ui.ts            # 预览卡样式（全量 --dsw-* token）
```

数据流：

```text
按钮/快捷键 → trigger() → POST /session-handoff/prepare
  → previewStore.ready(payload) → 预览卡（可编辑）
  → 打开新会话（用编辑后的提示词 + 最近工作区）
  → previewStore.idle()
```

## 4. 接口变更（兼容）

`POST /session-handoff/prepare` 响应新增：

```json
{
  "promptParts": {
    "title": "…", "sessionId": "…", "docPath": "…", "dataPath": "…",
    "summary": "…", "goal": "…", "completed": ["…"],
    "nextSteps": [{ "step": "…", "why": "…" }], "blockers": [],
    "references": ["…"], "referenceOptions": ["…"], "requirements": ["…"]
  },
  "preview": true
}
```

- `promptText` 继续返回，旧客户端不受影响；
- `preview` 来自配置，缺省 true；
- `GET /session-handoff/health` 的 `config` 增加 `preview`。

## 6. 与设计的偏差（明确记录）

1. **@ 引用 chip → 路径清单**：DSH 的引用 chip 由输入触发器（`ui-input-trigger`）内部管理，没有公开的
   「插入引用」动作；写提示词里的绝对路径是可验证、跨版本稳定的做法。v0.3 若出现公开 API 再升级。
2. **记忆插件适配器 → 候选展示 + 本地台账**：调研的 mnemon/meow-memory/mneme 各自存储、无统一协议；
   直接写会绑死私有实现。v0.2 保证「候选可见、台账可删」，待生态出现公开契约再适配。
3. **`/handoff` 命令延期**：命令结果只能返回文本并展示，无法创建/导航会话；单独实现会产生
   「生成文档但不继续」的半成品。等 `conversation.chat.commandview` 类方案成熟再做。

## 10. 线上反馈修复（v0.2.2）

真实安装后点「接力」报错：`Handoff failed: cannot get property "llm" without inject`。

**根因**：宿主半在 `prepare` 里把原始 cordis `ctx` 直接传给 `summarize()`，后者读 `ctx.llm`。
`llm` 未写进 `inject`（它是可选能力），cordis 4 的插件作用域是严格代理，直读可选服务会抛错，
而不是返回 undefined。冒烟测试用的是普通对象 ctx，所以没有暴露。

**修复**：
- `prepare` 先用 `service(ctx, 'llm')`（内部 `ctx.get(name, false)`）解析成普通对象，再传 `{ llm }`；
- 复查同类写法：`sessionQuery`/`sessions`/浏览器半 `shortcuts`/`locale`/`uiWorkspace` 全部走软取；
- 冒烟测试改用严格 Proxy（直读未注入服务即抛错），宿主当时 44 项（v0.2.3 增至 53 项）、浏览器 34 项，覆盖该类回归。

**教训**：cordis 的 `ctx.get(name, false)` 是唯一合法的可选服务读取方式；「传 ctx 给子模块」等于把注入约束扩散出去。

## 11. 真实交接产物复查（v0.2.3）

用户在长会话里点了两次交接，生成了两份文档；新会话实际使用的是第二份（降级版）。逐份核对后：

| 检查项 | 结果 |
|---|---|
| 第一份（LLM，22KB） | 结构完整、结论与仓库事实一致（5726f44/62f4ead/1.9.3/文档目录均核对通过）；记忆候选 6 条写入台账 |
| 第二份（降级，22KB） | 结构完整但内容不合格：已完成出现「```dsh-ui」、当前状态是被截断的 UI JSON、标题取会话首条消息、下一步泛化 |
| 新会话提示词 | 指向第二份文档；虽然模型读文档后仍能推断，但交接质量明显下降 |
| 参考文件 | 第一份 34 条中仅 1 条畸形路径不存在；第二份混入 /tmp 截图与畸形路径 |
| memory 台账 | 6 条内容合理，但时间戳是 UTC（20:28）而非本地（04:28） |

**根因与修复**：

1. **标题**：SessionHeader.title 为空，标题在 `session/title` 事件里；采集器补读最新事件（本例应为「项目工程分析」）。
2. **max-tokens**：DeepSeek reasoning 计入输出预算，4096 被吃满后整单降级。默认提到 8192；`max-tokens` 先尝试解析，
   失败才翻倍重试一次（上限 16384）。
3. **兜底质量**：新增 `proseOf()` 剥离代码围栏/dsh-ui JSON/标题/表格行；完成项与现状只取可读段落；
   标题回退到最近诉求；历史工具失败标注「历史失败」，不再冒充当前阻塞。
4. **参考文件**：`filterReferences()` 过滤不存在的绝对路径，工作区内优先，tmp/畸形路径不进提示词。
5. **台账时间**：改为本地时间戳。

**验证**：把真实会话日志（4820 事件）解压后喂给新构建做确定性生成——标题「项目工程分析」、
完成项为可读散文、无 dsh-ui/JSON 段落、参考文件只保留存在的路径；加上 9 项新冒烟（max-tokens 接受/重试、标题、兜底清洗、引用过滤）。

## 12. 按钮共存核查（v0.2.4）

问题：会话页这个按钮会不会覆盖其他插件注册到 `conversation.input.right` 的按钮？

**结论：不会。** 依据（DSH 0.2.1-rc.2 源码）：

- 座位声明是 `list`（`packages/client/ui-conversation/src/client/contract/slots.ts:278`）；
- `SlotCore.register` 对 list 的处理是「按 `id` 分格；只有相同 id + 相同 priority 才抛重复错误」
  （`packages/client/ui-slots/src/index.ts:1227-1240`），不同 id 一律追加；
- 渲染取每格 winner 后按 `order` 排序，格子之间不会互相替换（`entriesOfSlot`，同文件 1353-1375）；
- 本插件不传 `priority`，只声明 `order: 40` 与唯一 id；按钮 CSS 只命中 `.dsh-handoff-btn`；
- 实机核查：当前 profile 里唯一同座位的第三方注册是 `dsh-connect-qoder` 的 `qoder-composer-pill`
  （`order: 4`），与本按钮并存（它是余额读数，在左；本按钮在右）。

**唯一会挡住其他按钮的时刻**：用户主动打开预览卡时的全屏遮罩；它关闭后页面恢复，且从不注销任何插件的注册项。

**加固**：把按钮/预览卡的 cell id 从泛化的 `session-handoff` 改为包名限定的
`dsh-session-handoff` / `dsh-session-handoff-preview`，把「第三方恰好用同名 id」的理论碰撞概率降到可忽略；
产物自检增加唯一 id 项（32/32）。
